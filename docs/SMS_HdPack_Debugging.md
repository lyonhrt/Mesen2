# SMS HD Pack Debugging Guide

## ?? **Current Implementation Status**

### ? **What We Have:**
1. **Auto-start system** - SMS HD packs automatically start dumping when an SMS game loads
2. **Auto-stop system** - HD packs automatically save when games are closed  
3. **Test tile generation** - Creates dummy tiles to verify the save system works
4. **Extensive logging** - Debug messages to track what's happening
5. **Standard save location** - Uses the same folder as NES HD packs

### ?? **Debugging Steps to Follow:**

## **Step 1: Check if Auto-Start is Working**

1. Load an SMS game in Mesen2
2. Open the **Log Window** (Tools ? Log Window)
3. Look for these messages:
[SMS HD Pack] ?? AutoStartOnGameLoaded called
[SMS HD Pack] Console type: [number]
[SMS HD Pack] Is SMS console: YES/NO
[SMS HD Pack] ? SMS console detected - starting tile dumping!
[SMS HD Pack] ? Successfully started SMS tile dumping!
[SMS HD Pack] Save folder: [path]
[SMS HD Pack] Test tile added - will save when game closes
## **Step 2: Check Console Type Detection**

If you see "Is SMS console: NO", the problem is console type detection.

**Supported SMS console types:**
- Master System (.sms files)
- Game Gear (.gg files)  
- SG-1000 (.sg files)
- ColecoVision (.col files)

## **Step 3: Test Manual Save**

The system adds a test tile automatically. To verify the save system:

1. Load an SMS game
2. Close the game (File ? Power Off)
3. Look for these messages:[SMS HD Pack] Stopping SMS tile dumping and saving...
[SMS HD Pack] ? SMS tile dumping stopped and saved
## **Step 4: Check Save Location**

HD packs should be saved to:

**Windows:**C:\Users\[USERNAME]\Documents\Mesen\HdPacks\[RomName]\hires.txt
**Linux:**
/home/[USERNAME]/Documents/Mesen/HdPacks/[RomName]/hires.txt
## **Step 5: Check File Contents**

If the `hires.txt` file is created, it should contain:
<ver>100
<scale>1
# SMS/Game Gear HD Pack - Generated by Mesen2
# ROM: [YourRomName]
<tile>0,AAAA55555555AAAA55555555AAAA55555555AAAA55555555AAAA55555555AAAA55555555,FF336699,10,20,1.0,N
## **?? Troubleshooting Issues:**

### **Issue: No log messages appear**
- **Problem:** Auto-start hook not called
- **Solution:** Check if `SmsHdPackApi::AutoStartOnGameLoaded(this)` is in `Emulator::InternalLoadRom`

### **Issue: "Not an SMS console" message**
- **Problem:** Wrong console type detected
- **Solution:** Check file extension and console detection logic

### **Issue: No HD pack folder created**
- **Problem:** `FolderUtilities::GetHdPackFolder()` not working
- **Solution:** Check if Documents/Mesen folder exists and has write permissions

### **Issue: Auto-start works but no save on close**
- **Problem:** Stop hook not called
- **Solution:** Check if `SmsHdPackApi::StopHdPackDumping(this)` is in `Emulator::Stop`

# SMS HD Pack System - Debugging Results Summary

## ?? **Issue Identified and Fixed!**

### **Root Cause:**
The SMS HD pack dumping system was failing to create files due to **invalid characters in the ROM filename**. The original ROM name was:
"Castle of Illusion Starring Mickey Mouse (USA, Europe, Brazil) (En) (Rev 1)"
This contains problematic characters for Windows filesystems:
- **Parentheses**: `()` 
- **Commas**: `,`
- **Mixed path separators**: `/` and `\`
- **Very long filename**: 80+ characters

### **Solution Implemented:**

1. **ROM Name Sanitization** - Added `SanitizeRomName()` function that:
   - Replaces `()[]{},:;"'<>|?*/\` with `_`
   - Limits length to 80 characters to prevent path-too-long errors
   - Removes trailing dots and spaces
   - Provides fallback name if sanitization results in empty string

2. **Enhanced Error Handling** - Added comprehensive logging to track:
   - Directory creation status
   - File creation attempts
   - Stream state diagnostics
   - Path validation

3. **Filesystem Compatibility** - Uses standard C++ filesystem methods for cross-platform compatibility
